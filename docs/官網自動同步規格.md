# 官網 → 記帳系統 自動同步規格（給官網工程師）

## 要做的事（一句話）

官網的**訂單**或**商品**（課程、書籍、優惠碼）有變動時，官網**伺服器**呼叫記帳系統的 API，把最新資料 POST 過去。

記帳系統那邊已經做好，官網只要負責「送」。原本後台用的書籤手動同步會保留，當作備援。

---

## 1. 連線方式

| 項目 | 內容 |
|---|---|
| 網址 | `https://<記帳系統 API 網域>/api/web-orders/push`（管理員會給完整網址） |
| 方法 | `POST` |
| Header | `Content-Type: application/json`<br>`Authorization: Bearer <自動同步金鑰>` |
| 金鑰 | 管理員在記帳系統「官網對帳 › 官網自動同步」按「產生自動同步金鑰」後交給你，開頭是 `lxs_` |

- 建議把網址和金鑰放進官網的環境變數（Vercel → Settings → Environment Variables）：`LEVIAX_ACCOUNTING_PUSH_URL`、`LEVIAX_ACCOUNTING_PUSH_KEY`。
- **只能從伺服器端呼叫**（API Route、Server Action、Webhook handler、Cron）。金鑰不能出現在前端程式或瀏覽器裡。
- 金鑰重新產生後，舊的會立刻失效（會回 401），這時要換成新的金鑰。

---

## 2. 什麼時候要送

| 時機 | 送什麼 |
|---|---|
| 新訂單成立 | `orders: [這張訂單]` |
| 訂單狀態改變（付款、開通、完成、取消，或後台改了金額或品項） | `orders: [這張訂單的最新完整資料]` |
| 課程有新增、修改、刪除 | `catalog.courses`：**全部課程**的完整清單 |
| 書籍（單品、組合包、行事曆）有新增、修改、刪除、上下架 | `catalog.books`：**全部書籍**的完整清單 |
| 優惠碼有新增、修改、停用、刪除 | `catalog.coupons`：**全部優惠碼**的完整清單 |
| 每天一次，建議凌晨（Vercel Cron） | 全量備份：所有訂單＋三種商品的完整清單 |

規則：

- 同一個 request 裡 `orders` 和 `catalog` 可以一起送，也可以只送其中一個。
- **重複送沒關係**：訂單以 `orderNo` 為準，有就更新、沒有就新增。商品以名稱或代碼為準。
- 商品清單一送就是**整份**。某一份沒出現的項目，記帳系統會把它標成停用（不會刪掉）。
  - 只改了書籍，就只送 `catalog.books`。沒送的那幾份清單不會被動到。
  - 不要只送「改了的那一本書」，這樣其他書都會被停用。
- 送失敗（網路錯誤或 5xx）時請重試，例如 1 分鐘、5 分鐘、30 分鐘後各重試一次。
- 推送失敗**不要擋住**官網本身的流程：顧客下單、後台改狀態都要照常成功，推送放在背景做（`waitUntil`、佇列，或 try/catch 後記 log 就好）。
- 每天的全量備份會補回漏掉的資料，所以偶爾失敗不會漏帳。

---

## 3. 資料格式

### 3.1 整體

```json
{
  "orders": [ ...訂單... ],
  "catalog": {
    "courses": [ ...課程... ],
    "books":   [ ...書籍... ],
    "coupons": [ ...優惠碼... ]
  }
}
```

除了下面標成「選填」的欄位，其他欄位都必填。每一個欄位都可以省略，用 `{}` 呼叫就是一次連線測試。

### 3.2 訂單 `orders[]`

```json
{
  "orderNo": "LX-20261029-001",
  "orderedAt": "2026-10-29T14:05:31+08:00",
  "buyer": "王小明",
  "total": 10125,
  "discount": 1125,
  "status": "paid",
  "statusLabel": "課程已開通",
  "items": [
    { "name": "物理先修課程", "price": 11250, "preorder": false, "bundle": false }
  ]
}
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `orderNo` | string | 官網訂單編號，格式一定要是 `LX-YYYYMMDD-NNN` |
| `orderedAt` | string | 下單時間，ISO 8601，**要帶時區**（`Z` 或 `+08:00`）。沒帶時區的話會當成台灣時間 |
| `buyer` | string | 買家姓名，就是後台訂單卡片第一行顯示的名字 |
| `total` | int | **實付金額**（折扣後），新台幣整數 |
| `discount` | int | 選填，折扣金額（優惠碼、早鳥加總），預設 0 |
| `status` | enum | 見下表 |
| `statusLabel` | string | 選填，後台畫面上顯示的狀態文字，例如「課程已開通」「已出貨」 |
| `items[].name` | string | 品名，要跟後台訂單卡片上顯示的品名一樣（課程名稱、書名、組合包名） |
| `items[].price` | int | 這一項的價格（原價） |
| `items[].preorder` | bool | 選填，是否預購 |
| `items[].bundle` | bool | 選填，是否組合包 |

`status` 只能是下面四個值之一：

| 值 | 意思 | 對應後台分頁 |
|---|---|---|
| `pending_payment` | 還沒付款 | 待處理 |
| `paid` | 已付款，還在處理（開通、出貨中） | 待處理 |
| `completed` | 訂單完成 | 已完成 |
| `cancelled` | 已取消 | 已取消 |

> 記帳系統靠 `status` 判斷有沒有付錢，`pending_payment` 會算進「應收帳款」。請一定照實際付款狀態給，不要把已付款的訂單送成 `pending_payment`。

### 3.3 課程 `catalog.courses[]`

```json
{ "name": "物理先修課程", "category": "online", "subject": "物理", "price": 15000 }
```

| 欄位 | 說明 |
|---|---|
| `name` | 課程名稱，跟後台「課程管理」顯示的一樣 |
| `category` | `online`＝線上課程，`tutoring`＝小班家教 |
| `subject` | 科目：`物理`、`化學`、`生物`、`地科`、`數學`。記帳系統用它自動對應主理老師 |
| `price` | 定價（整數） |

### 3.4 書籍 `catalog.books[]`

```json
{ "name": "物理（上）", "kind": "book", "price": 980 }
```

| `kind` | 什麼東西 | `name` 的寫法（**請照這個規則，記帳系統已經用這些名稱記過帳**） |
|---|---|---|
| `book` | 講義單品 | 單品名稱，例：`物理（上）`、`地科先修課程` |
| `workbook` | 刷題本單品 | 單品名稱，例：`物理刷題本（上）` |
| `bundle` | 組合包 | `科目 組合包名稱`，中間一個半形空白，例：`物理 四本全套`、`地科 全套（講義＋刷題本）` |
| `notebook` | 行事曆 | `商品名稱（單品名稱）`，例：`科學班倒數行事曆（2026 8月-2027 3月）` |

- 「科目」就是書籍商品名稱去掉結尾的「先修課程」，例如「物理先修課程」變成「物理」。
- 已下架或停售的品項不要放進清單。不在清單裡的，記帳系統會標成停用。

### 3.5 優惠碼 `catalog.coupons[]`

```json
{ "code": "LEVIAX001", "discountRate": 0.05, "validUntil": null, "active": true }
```

| 欄位 | 說明 |
|---|---|
| `code` | 優惠碼，只能有英數字、`_`、`-` |
| `discountRate` | 折扣比例，0～1（5% 折扣寫 `0.05`） |
| `validUntil` | 到期日 `YYYY-MM-DD`，沒有期限寫 `null` |
| `active` | 後台是否「啟用中」 |

---

## 4. 回應

| 狀態碼 | 意思 | 要怎麼處理 |
|---|---|---|
| `200` | 成功，例：`{"ok":true,"count":1,"syncedAt":1793242608521,"catalog":null}` | — |
| `400` | 格式不對，`error`、`detail` 會說明哪個欄位錯 | 不要重試，修程式 |
| `401` | 金鑰不對或已重新產生 | 不要重試，請管理員給新金鑰 |
| `5xx` 或網路錯誤 | 記帳系統暫時有問題 | 稍後重試 |

單次上限：訂單 5000 張、課程 500 門、書籍 1000 項、優惠碼 500 組，大小約 2 MB。

---

## 5. 隱私（重要）

**不要送**電話、地址、Email、取貨門市、匯款帳號或末五碼、身分證字號。記帳系統只需要上面列的欄位，送了其他欄位也會被丟掉，但請在官網這邊就不要送。

---

## 6. 範例

### curl 測試

```bash
curl -X POST "$LEVIAX_ACCOUNTING_PUSH_URL" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $LEVIAX_ACCOUNTING_PUSH_KEY" \
  -d '{}'
# 預期回應：{"ok":true,"count":0,...}
```

### Next.js（TypeScript）

```ts
// lib/accountingPush.ts
type PushBody = { orders?: unknown[]; catalog?: { courses?: unknown[]; books?: unknown[]; coupons?: unknown[] } };

export async function pushToAccounting(body: PushBody) {
  const url = process.env.LEVIAX_ACCOUNTING_PUSH_URL;
  const key = process.env.LEVIAX_ACCOUNTING_PUSH_KEY;
  if (!url || !key) return; // 還沒設定就跳過，不影響官網
  for (const wait of [0, 60_000, 300_000]) {
    if (wait) await new Promise((r) => setTimeout(r, wait));
    try {
      const res = await fetch(url, {
        method: "POST",
        headers: { "Content-Type": "application/json", Authorization: `Bearer ${key}` },
        body: JSON.stringify(body),
      });
      if (res.ok) return;
      if (res.status === 400 || res.status === 401) {
        console.error("accounting push rejected", res.status, await res.text());
        return; // 格式或金鑰問題，重試也沒用
      }
    } catch (e) {
      console.error("accounting push failed", e);
    }
  }
}

// 訂單建立／狀態更新後（不要 await 擋住回應；Vercel 上可用 waitUntil）
//   waitUntil(pushToAccounting({ orders: [toAccountingOrder(order)] }));
// 書籍有任何變動後
//   waitUntil(pushToAccounting({ catalog: { books: await listAllBooksForAccounting() } }));
```

`toAccountingOrder`、`listAllBooksForAccounting` 請依官網的資料表自己寫，把資料轉成第 3 節的格式。

### 每日全量（vercel.json）

```json
{ "crons": [{ "path": "/api/cron/accounting-full-sync", "schedule": "0 19 * * *" }] }
```

`0 19 * * *` 是 UTC 19:00，等於台灣凌晨 3:00。這支 route 要送出所有訂單和三份完整商品清單。

## 7. 驗收清單

- [ ] 用 curl 送 `{}` 回 200。
- [ ] 下一張測試訂單，記帳系統「官網對帳」在 1 分鐘內出現，顯示「應收（待付款）」。
- [ ] 把那張訂單改成已付款，記帳系統狀態跟著變。
- [ ] 改一本書的價格，記帳系統的書籍價格跟著變，其他書沒有被停用。
- [ ] 新增或停用一組優惠碼，記帳系統跟著變。
- [ ] 每日 Cron 有跑，記帳系統「官網最後推送」的時間有更新。
- [ ] 送出的資料裡沒有電話、地址、末五碼。
- [ ] 推送失敗時，官網下單和後台操作照常成功。

有問題請找記帳系統管理員（蔡睿軒）。
